## Fixtures

`packages/experiments/tests/data/system_jobs_golden.json`: per smoke job spec (`s1/STAGE/SEED/J/SHORT[/MAX_LABELS]`, `s2c/...`, `s2a/CONF_STAGE/SEED/ARM/SHORT`, `s3/STAGE/SEED/ARM/SHORT`) the unit and label counts and energy of the OLD record (the test compares energy at rtol 1e-3). Generated by the OLD drivers (`e6p_discovery.episode_job`, `e6p_conf.episode_job` / `arm_job`, `e6p_certsafe.arm_job`) with `smoke=True` on Windows with CDD-ORAN's environment (Windows 11, Python 3.12.13, numpy 2.4.2).

```text
python make_golden.py OLD.jsonl system_jobs_golden.json
```

## Gates against the stored Study 1, 2 and 3 records

Run on the VPS (Python 3.14.4, numpy 2.5.4, single-thread BLAS); the old code ran there from a read-only copy of `CDD-ORAN@0c89106`.

**Episode jobs (`study1_raw`, `study2_raw`, `study2_3_decision/runs`).** 96 jobs: Study 1 dev 188000/1, eval 188100/1, placebo 188700/1; Study 2 dev_conf 186080/1, disc 186100/1, the three repro arms on 186080/1 and every eval arm on 187000/1; Study 3 dev `CAL:allaccept` and `noarb` on 191000/1 and every eval arm on 191100/1. Old and new code agree on all 96 (every field except timing). Against the Kaggle records, 80 are bit-identical; the other 16 (all 10 collection episodes, and the arm jobs 186080 `incumbent`, 187001 `sub:SliceGuarantee` / `sub:PowerES` / `B2`, 191100 `MG:PMRT`, 191101 `CS:qacm@dev`) differ by one UE in one sample tick in the plant (active-UE context sums by 0.008 to 0.032, eMBB violation counts by 1 to 7, energy), and the old code gives exactly the same differences, so they come from the Kaggle stack (Python 3.12.13, numpy 2.4.2).

**Discovery tests (`study1_raw/e6p-disc-v4an-pmrt-1/out/analysis_v4.json`, `study2_raw/e6p-conf-discan-2/out/disc_conf.json`).** From the frozen caches, with the SHAP import blocked so both sides use the GBDT permutation fallback the Kaggle runs used. Study 1: `gt`, `data`, `slices`, `placebo_units`, K0, all placebo and K0n descriptive blocks and the K0n primary inputs are equal, and so is every declaration of every method on the placebo and the 18 slices except `qacm` on `s300_1` (9 vs 10 edges, the stack difference found in phase 7). The rest differ in floats only: Granger p rel <= 2.8e-10, baseline Granger tau 5.6e-12, the torch `two_tower` descriptive tau 7.5e-5, z values ~1e-16. Study 2: no non-float difference (maps, declarations, aliases, decision tables, edge quality, replay, K0, K0n equal); map scores rel <= 5.3e-14, `granger_ctx` p <= 1.9e-6, torch `two_tower` taus <= 1.6e-4, and the `shap_gbdt` fallback `tau_dev` 0.016773422278405115 vs 0.01634739707545272 with the same map. On the VPS the old Study 1 analyzer (run without the descriptive methods and the null outcome) equals the new tests on every field except the `wall_s` timings, and the old and new SHAP fallbacks both give 0.016773422278405115, so the float differences come from the Kaggle stack (scikit-learn, numpy).

**Referee artifacts.** `artifacts.build_maps` from `study2_raw/e6p-conf-discan-2/out/disc_conf.json` and `artifacts.build_certsafe` from the frozen bounds and calibration inputs rebuild `packages/experiments/artifacts/E6P_CONF_MAPS.json`, `E6P_CERTSAFE.json` and their `.sha256` files byte for byte (Windows and VPS); `verify_maps` / `verify_certsafe` accept them, and `calibrate` on the DEV records rebuilds `certsafe_calib.json` except its `argv`. The sha256 pins of the old analyzer, driver, `mapgate.py` and `certsafe.py` that the artifacts embed are kept as constants in `common.py` (`LEGACY_SHA256`). The Study 2 / 3 run headers carry what the referee analyses filter on, as the old drivers wrote them: `driver` `e6p_conf` / `e6p_certsafe`, `conf_stage` / `cs_stage`, `platform` (= `numeric_env`), `mapgate_sha256` and (Study 3) `certsafe_sha256` (the pins), and `code` from `campaign.provenance.code_info` (launcher environment, git, bundle manifest).
